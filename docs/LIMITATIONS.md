# Known limitations and next validation work

13. **Event hypotheses are not verified incidents.** Cross-source clustering produces review candidates only. It does not prove that reports describe the same real-world event, and it does not create or verify incidents. Analysts must confirm or reject associations.
14. **Event-pair ranking is not calibrated.** The optional supervised model returns an uncalibrated candidate-ranking score. The bundled pair fixture is synthetic software-test data, not evidence of real disaster-detection performance. No claim is made that the trained ranker is better than the heuristic baseline.
15. **Multilingual semantic matching is optional and locally staged.** SentenceTransformer support is off by default, requires the optional ML dependencies and model files already present on the host, and will not download weights during discovery. Domain quality, language coverage, inference latency and memory requirements remain unevaluated on representative data.
16. **Source profiles are descriptive.** Operational ingestion success and analyst association acceptance are distinct measurements. Neither proves source truthfulness, completeness, independence or lack of bias. These profiles are not currently used to alter event scores.
17. **Event snapshots are observation snapshots, not ground truth history.** They record states observed by Cignal discovery and review workflows. They cannot reconstruct changes that occurred between Cignal observations.
18. **Discovery is bounded and analyst-triggered.** It is not yet continuous stream processing, a real-time early-warning service or an independently validated operational alerting system.
19. **Training requires representative, traceable labels.** The supervised pair trainer requires group-disjoint splits and a separate untouched final holdout. Synthetic fixtures are smoke tests only. Labels need reviewer provenance, legal basis, privacy review and geographic/language coverage before model-quality claims.
20. **Model artifacts are trusted local inputs.** Event-pair artifacts use joblib serialization. Only load artifacts produced by the trusted Cignal training workflow; loading an untrusted artifact can execute code.

1. **NiceGUI is server-driven.** The main dashboard and interactions need an active connection to the frontend server. The service worker caches a minimal shell; it does not make the whole NiceGUI app functional offline.
2. **Offline report drafts are limited.** A small browser bridge stores an anonymous report draft in local storage and retries while the page remains open and connectivity returns. It does not support reliable background sync with the browser closed, offline attachments, authenticated offline drafts, conflict resolution, or a fully offline map. The report is submitted anonymously on retry. This browser bridge is the narrow exception to Python-only application code needed for browser-side storage; main frontend behavior remains Python/NiceGUI.
3. **PWA browser support varies.** Service workers and Web Push require HTTPS or localhost; install prompts and push permission behavior are browser-dependent.
4. **NLP model quality is not operationally validated.** The default compact multilingual seed model is a prototype baseline. Scores are not calibrated. The optional SentenceTransformer is a generic semantic embedder. Expand and evaluate on licensed, representative, human-labelled datasets before operational use.
5. **Image analysis is generic.** Optional MobileNet V3 Small returns broad ImageNet categories. It does not identify disaster severity, casualties, structural integrity or evacuation need.
6. **Location extraction is basic.** It extracts literal coordinate pairs and a small built-in city alias table. It does not perform multilingual geocoding or authoritative administrative-boundary resolution.
7. **Duplicate detection is heuristic.** Token similarity + distance produces candidate links only. It is not entity resolution and can miss duplicates or suggest false matches.
8. **Predictive risk modelling is not implemented as a validated feature.** Analytics aggregate records in the database; forecasts come from weather context providers. No autonomous risk score or emergency declaration is made.
9. **Data access depends on provider terms.** IMD may require an account/token and precise endpoint; NASA FIRMS requires a free MAP_KEY; Open-Meteo free access has non-commercial/attribution conditions; social data needs an authorised provider API. Check current terms and usage limits before every deployment. Source adapters are not a guarantee of access.
10. **Public access without a domain is temporary.** Cloudflare Quick Tunnels offer a random URL for development/testing only, with no uptime guarantee and a current 200 in-flight-request ceiling. This cannot serve as stable production infrastructure.
11. **Capacity has not been benchmarked.** A 16 GB CPU-only personal machine is unlikely to be a dependable 100–500 concurrent-user production host without measurement and infrastructure upgrades.
12. **Security is not certification.** No third-party penetration test, malware-scanning pipeline, account email verification, password reset flow, SIEM integration or formal disaster-response certification is included.
